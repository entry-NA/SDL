# AEEM Core Ablation Protocol

## Purpose

The core progressive ablation uses three groups to attribute the two claimed
innovations:

| Group | Pseudo-label source | What the comparison demonstrates |
|---|---|---|
| A0 | Original UCOD-DPL 16x16 pkl | Reproduction baseline |
| A1 | Frozen SAM2, legacy `--mode naive` labels | A1 - A0: offline zero-shot SAM2 paradigm |
| A2 | AEEM v2 m4 composed labels | A2 - A1: adaptive edge-aware system |

All three groups use DINOv2-base, 518x518 input, batch size 16, 25 epochs,
seed 42, fp16, EMA 0.99, `merge_method=dis`, and Look-Twice with threshold
0.15. Only the pseudo-label source changes.

## Reuse Decision

- A0 must be retrained. Its old work directory was reused and the default
  refined-label directory was updated while the 2026-07-23 training job was
  still running, so the resulting checkpoint is not an isolated baseline.
- A1 labels can be reused. There are 4028 PNG labels generated by
  `offline_sam2_refine.py --mode naive`; the 12 samples with empty coarse masks
  intentionally fall back to their original pkl labels. During loading, those
  16x16 fallbacks are resized to the same 68x68 tensor shape as the PNG labels.
  A1 must be retrained because no independently identifiable checkpoint remains.
- A2 can be reused from experiment
  `m4_camo_all_cod10k_qsemantic25_20260724_v1`.

The legacy script accepts `naive`, not `native`. Because its hand-written
argument parser does not validate values, `--mode native` silently processes
neither branch and generates zero masks.

## Commands

Run from the repository root in the `test01` environment.

```powershell
& .\scripts\run_core_ablation_train.ps1 -Group a0 -PreflightOnly
& .\scripts\run_core_ablation_train.ps1 -Group a0
& .\scripts\run_core_ablation_eval.ps1 -Group a0

& .\scripts\run_core_ablation_train.ps1 -Group a1 -PreflightOnly
& .\scripts\run_core_ablation_train.ps1 -Group a1
& .\scripts\run_core_ablation_eval.ps1 -Group a1
```

A0 and A1 are independent; they may be run in either order. Do not run both
training jobs concurrently on the same GPU.

## Interpretation Rule

Use the same five reported metrics for every group. The core claims require:

- A1 should improve boundary-sensitive metrics over A0 without a material
  regression in SMeasure or MAE.
- A2 should improve stability across datasets relative to A1, especially on
  CHAMELEON, TE-COD10K, and NC4K.

Do not choose a different epoch per test dataset. Use `epoch25.pth` for every
dataset and report all four results, including regressions.
