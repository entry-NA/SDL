数字有没有增加。 第九章 常见错误速查 以下是我们实际踩过的坑，按出现频率排列。 错误 1：ModuleNotFoundError: No module named 'sam2' 原因：SAM2 没装在 test01 环境。 解决：conda activate test01 然后 pip install git+https://github.com/facebookresearch/sam2.git 错误 2：FileNotFoundError: datasets\cache\... 原因：junction 连接没创建或路径不对。 解决：回到 2.2 节重新创建连接，然后用 dir 验证。 错误 3：CUDA out of memory 原因：8GB 显存不够（浏览器、游戏等占用了显存）。 解决：关掉所有不用的程序（特别是 Chrome），重跑。如果还不行，修改配置文件里的 batch_size 为 8。 错误 4：终端输出乱码 原因：Windows 默认编码 GBK 不支持 Unicode 字符。 解决：set PYTHONIOENCODING=utf-8。如果还是乱码，不用管——数字部分通常是正常的。 错误 5：特征提取时卡住不动 原因：DINOv2 下载模型权重时网络慢。 解决：等。首次下载约需 1-2 分钟。之后会缓存。 错误 6：bash: command not found 原因：没装 Git for Windows，bash 不可用。 解决：装 Git for Windows，或者把 .sh 文件里的命令手动复制到 cmd 执行。 错误 7：训练报错 "Not working on read mode!" 原因：伪标签缓存路径不存在。 解决：检查 datasets/cache/pseudo_label_cache/TR-CAMO+TR-COD10K/ 下是否有 data_0.pkl。如果没有，回到 2.2 节创建连接。 错误 8：评估结果和预期相差很大（SMeasure 差 &gt; 0.01） 原因：可能是用了错误的检查点（比如 epoch5 而不是 epoch25），或者精修标签没有正确加载。 解决：确认 -m 参数指向 epoch25.pth，确认 datasets/cache/refined_pseudo_labels/ 有 4040 个文件。
